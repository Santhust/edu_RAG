Follow a question

One question takes two paths through this repo: an offline build that turns a PDF into searchable chunks, and an online path that turns the question into a cited answer. This page follows the online path, stage by stage, using the real functions.

Worked example

One question, four passages

Question: “Where was the bodhisatta born?”

Retrieval scores all 1,404 chunks. These are the top four under hybrid ranking — the passages the generator will actually see:

#ChunkFusedLexicalDenseSource
1c00300.860.170.67pp. 16-17, Birth
2c00320.830.160.68pp. 17-18, Birth
3c00230.800.100.80p. 14, Birth
4c00310.700.110.69p. 17, Birth

Those four excerpts go into the prompt. With only them as evidence, the model answers:

The bodhisatta was born into the Sakya family of the noble-warrior caste. His father was named King Suddhodana and his mother was named Queen Maya. The capital city of their lineage was Kapilavatthu, located in the northwest of the Ariyan world—the middle Ganges valley. [p. 14, Birth]

Everything below explains how those numbers were produced. The complete traces are in demo 01 and demo 02 further down this page.

What already exists before you ask

ingest runs once. It cleans the PDF into labelled pages (pages.json), slices those pages into 1,404 overlapping chunks (chunks.jsonl), and builds two indexes over the chunk texts: a sparse TF-IDF matrix (lexical.joblib) and, optionally, 384-dimensional semantic vectors (dense-fastembed-BAAI_bge-small-en-v1.5.npy). A question never touches the PDF; it reads these four files.

Seven stages from question to context

  1. Settings. config.py merges environment variables, a JSON file and dataclass defaults. One detail matters here: the saved default says embed=tfidf, while the dense file on disk was built with fastembed. Both demos detect the backend from the filename so the trace actually shows hybrid retrieval.
  2. Chunks. The Retriever loads all 1,404 chunks. Every chunk carries its own page span and chapter, which is where citations come from later.
  3. Lexical scores. The question is vectorised with the saved TF-IDF vectorizer and dotted against the sparse matrix. Both vectors are length-normalised, so the result is a cosine similarity per chunk. Only 118 chunks score above zero for the example question.
  4. Dense scores. The question is embedded with bge-small-en-v1.5 and dotted against the 1,404 × 384 matrix. Again cosine similarity, but in a 384-dimensional semantic space where related wording lands close together.
  5. Fusion. The two score ranges are very different — roughly 0.00–0.17 lexical against 0.33–0.80 dense. Adding them raw would let dense dominate, so _minmax() rescales each list to 0–1 separately before the 0.50 / 0.50 weighted sum. The fused numbers are relative ranks, not probabilities.
  6. Ranking. An optional chapter filter narrows the candidate indices, then np.argsort(-final)[:k] selects the top four.
  7. Context. format_context() turns those chunks into a numbered block of excerpts with their citation headers. That block becomes the user message. Nothing later can fetch more evidence.

From context to answer

prepare() wraps the excerpts in a system prompt that says: use only these excerpts, cite every sentence, say “I don't know based on the book” when unsupported, stay under 150 words. llm.chat() hashes the backend, model, full message list, temperature, token cap and thinking flag into a cache key. On a hit it returns the stored answer; on a miss it POSTs to Ollama or an OpenAI-compatible endpoint, caches the result and logs usage. finalize() packages the text, the four passages and the response metadata into an Answer object.

Three things worth noticing

  • Dense retrieval reorders the same chunks: c0023 is fourth with lexical alone but third with hybrid, because dense gives it 0.80 while lexical gives it only 0.10.
  • The per-sentence citation rule and the “I don't know” fallback are prompt instructions, not Python checks. evaluate.py is what measures whether the model follows them.
  • The cache key contains the whole prompt, so changing retrieval settings, k, the model or the token cap forces a fresh answer. Demo 02's captured output is a snapshot: a rerun after the cache is populated shows cached=True.
