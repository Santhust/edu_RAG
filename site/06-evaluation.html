Measure whether it works

The first five modules showed how the system works. This one asks whether it works: fourteen fixed questions, two retrieval settings, and three numbers that decide if the right evidence was found.

Worked example — fourteen questions, two settings

The golden set in eval/golden_qa.json pairs each question with the pages and chapter the answer should come from. rag/evaluate.py runs retrieval against that set and scores the result. Here are the measured numbers at k=8, copied from the repository README.

modepage recallMRRchapter accuracy
TF-IDF only71%0.3679%
hybrid (TF-IDF + fastembed)86%0.4893%

Page recall asks whether the pages cited by the golden answer appear among the retrieved chunks. MRR, mean reciprocal rank, rewards putting the first correct page near the top rather than somewhere in the eight. Chapter accuracy asks whether the retrieved chapter matches the expected one. Adding dense semantic matching lifted recall from 71% to 86% and chapter accuracy from 79% to 93%; it also moved the first correct evidence earlier, from 0.36 to 0.48.

That gain comes from the embedding model and the score fusion in retrieve.py, not from Chroma or LlamaIndex. Modules 04 and 05 changed how the system is built, not these retrieval numbers.

Answer quality is a separate question

Retrieval can be good while generation still fails. A full 14-question answer run with hybrid retrieval at k=4 gave qwen2.5:3b a 50% citation rate and a 0.79 average keyword score. That run was capped at 160 output tokens, which truncated some citations; with the default 700-token cap in ask, citations appear reliably. gemma3:1b scored 0% citations and produced off-topic answers on several questions.

Those answer-quality numbers were measured before the local default changed to lfm3:latest. They describe qwen and gemma, not the current default, which has not been benchmarked on this golden set. Model capability matters as much as retrieval: a cloud model usually gives the cleanest grounding behaviour, while the local models are kept for comparison.

Read the numbers honestly

Everything here was measured on one CPU-only machine, on one book, with fourteen golden questions. The table is evidence about this setup, not a promise about another corpus, model or machine. To reproduce or extend it, run eval --dry-run -k 8 for the retrieval-only metrics, or eval -k 4 for the slower full answer run. Partial results are saved after every question under data/cache/.

You can inspect the inputs and the scorer directly: the golden questions and the evaluation code. Every demo page also links its own source and captured output on GitHub.
